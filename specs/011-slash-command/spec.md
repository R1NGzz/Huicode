# HuiCode Slash Command Spec

## 背景

HuiCode 当前把所有斜杠命令直接写在 `cli.py` 的长串条件分支中，命令元数据、解析、执行、补全和界面状态彼此耦合。静态补全列表与实际分发逻辑也可能不一致；此前裸 `/resume` 虽然能补全，却没有对应分支，最终被当成普通用户消息送进 Agent Loop，造成不必要的模型请求、工具调用和权限确认。

本章要建立统一的命令注册、解析和分发机制。斜杠命令必须在用户回车入口处先于 Agent 被识别，本地管理操作不调用 LLM；只有明确登记为“提示词命令”的命令才把预设内容送入对话。命令实现通过界面控制接口工作，不直接依赖 Rich、prompt_toolkit 或标准输出细节。

## 目标

- 用统一注册中心管理命令名称、别名、帮助信息、类型、参数提示和处理函数。
- 确保所有斜杠输入在进入 Agent 前完成确定性解析和分流，避免本地命令误消耗 Token。
- 建立可测试的界面控制接口，使命令逻辑与当前 TUI 渲染实现解耦。
- 让命令帮助、别名、Tab 补全和实际分发始终来自同一份注册数据。
- 用 `[DEFAULT]` 和 `[PLAN]` 明确展示当前任务模式，并在命令切换后立即刷新。

## 冲突裁决与兼容策略

本章的新设定优先于现有行为，具体裁决如下：

- `/plan` 只进入 Plan Mode；不带任务时不请求模型，之后的普通输入按 Plan Mode 执行。
- `/do` 只退出 Plan Mode 并切回 DEFAULT；不再自动执行最近计划，也不自动发送“请根据最近计划继续执行”。
- `/session` 成为会话管理主命令，统一承接列表、恢复和清理能力。
- `/permission` 成为权限管理主命令，替代复数形式作为帮助和补全入口。
- `/status` 成为统一状态入口，聚合当前模式、Provider、上下文、Token、MCP、记忆和权限摘要。
- 用户可见的内置高频命令严格为十个：`/help`、`/compact`、`/clear`、`/plan`、`/do`、`/session`、`/memory`、`/permission`、`/status`、`/review`。
- 为避免现有用户脚本突然失效，`/sessions`、`/resume`、`/permissions`、`/perm`、`/config`、`/context` 作为隐藏兼容入口保留，但不出现在 `/help` 和 Tab 补全中。
- `/exit`、`/quit` 作为隐藏基础命令保留；`/verbose`、`/last` 作为隐藏兼容命令保留。本章不把它们计入十个高频命令。

## 功能需求

- F1：系统必须提供命令注册中心，集中管理命令定义并按规范化名称查找命令。
- F2：每条命令定义必须包含名称、别名、简短描述、用法示例、命令类型和处理函数；可以包含参数提示和隐藏标记。
- F3：命令类型必须支持三类：纯本地命令、影响界面或会话状态的命令、向对话发送预设提示词的命令。
- F4：注册中心必须在启动阶段检测命令名、别名以及名称与别名之间的大小写不敏感冲突；发现冲突时必须立即以致命配置错误退出，不得继续进入交互循环。
- F5：解析器必须对空输入早返回；只把第一个非空字符为 `/` 的输入识别为命令。
- F6：解析器必须把第一个空白前的部分识别为命令名，把剩余文本原样作为参数；命令名转为小写，参数大小写不得被修改。
- F7：未知命令不得发送给 Provider，必须显示中文错误，并提示使用 `/help`。
- F8：输入分流器必须位于用户回车入口：命令交给命令分发器，普通文本才调用 Agent。
- F9：命令处理函数必须通过统一界面控制接口执行，至少支持显示消息、发送用户消息、切换模式、查询 Token 状态和刷新状态展示。
- F10：界面控制接口不得暴露 Rich、prompt_toolkit 的具体对象；当前 CLI/TUI 通过适配器实现该接口。
- F11：模式展示必须使用 `[DEFAULT]` 和 `[PLAN]`；启动默认是 `[DEFAULT]`，执行 `/plan` 后立即变为 `[PLAN]`，执行 `/do` 后立即恢复 `[DEFAULT]`。
- F12：prompt_toolkit 输入必须使用注册中心生成补全项；隐藏命令和隐藏别名不得参与补全。
- F13：Tab 补全必须支持大小写不敏感匹配；单个匹配可直接补全，多个匹配显示候选菜单。
- F14：命令参数提示必须能显示在帮助和补全元数据中；本章不要求参数值的动态补全。
- F15：`/help` 默认按命令类型列出十个可见命令；`/help <command>` 显示名称、别名、说明、用法和参数提示。
- F16：`/compact` 必须直接调用现有上下文压缩流程并显示结果，不进入 Agent Loop。
- F17：`/clear` 必须清空当前消息、计划和上下文状态并开启新 session，但不得删除历史 session、长期记忆或配置。
- F18：`/plan` 必须切换到 Plan Mode；有多余参数时显示用法，不把参数发送给模型。
- F19：`/do` 必须切换到 DEFAULT；有多余参数时显示用法，不自动执行最近计划，也不调用模型。
- F20：`/session` 默认列出可恢复会话；支持 `resume <session-id>` 和 `clean` 子命令；缺少或非法参数时显示用法。
- F21：隐藏兼容命令 `/sessions` 和 `/resume <session-id>` 必须分别映射到 `/session` 的列表与恢复能力，行为与主命令一致。
- F22：`/memory` 默认显示记忆状态；支持 `update` 和 `rebuild` 子命令；非法参数显示用法。
- F23：`/permission` 默认显示当前权限模式和规则摘要；支持 `strict`、`default`、`permissive` 三个模式参数，并在切换后刷新状态展示。
- F24：隐藏别名 `/permissions` 和 `/perm` 必须映射到 `/permission`，但不出现在帮助和补全中。
- F25：`/status` 必须显示当前 `[DEFAULT]/[PLAN]`、Provider/model、上下文窗口和最近 Token、权限模式、MCP 状态、记忆状态；不得泄露 API key、认证 Header 或其他 secret。
- F26：隐藏兼容入口 `/config` 和 `/context` 必须由命令系统处理，不得继续保留在主输入循环的条件分支中。
- F27：`/review [focus]` 必须构造固定的代码审查提示词并通过界面控制接口发送给 Agent；可选参数作为审查重点追加，不能替换固定的缺陷、回归和测试风险要求。
- F28：提示词命令发送后必须复用普通 Agent 事件流、当前模式、权限系统、记忆和会话记录，不得建立第二套对话流程。
- F29：隐藏 `/exit` 和 `/quit` 必须安全关闭 MCP、记忆后台任务和会话文件后退出。
- F30：旧的命令条件分支和静态 `COMMANDS` 列表必须被注册中心和统一分流器替代，避免出现两份命令真相源。
- F31：README 必须更新十个高频命令、隐藏兼容行为、三类命令、模式标记和 `/review` 的 Token 行为。

## 非功能需求

- N1：本地命令和状态命令不得调用 Provider；自动化测试必须断言 Provider 调用次数为零。
- N2：命令名称和别名冲突必须在进入交互循环前发现，错误信息要包含冲突键和涉及的命令。
- N3：注册、解析、分发、补全和具体命令处理必须分层，核心逻辑可在无真实终端环境下单元测试。
- N4：新增代码和用户可见输出使用中文，并遵循现有 Python 3.11、unittest、Rich 和 prompt_toolkit 技术栈。
- N5：命令分发失败不得让 Agent Loop 或 CLI 崩溃；预期的参数错误以中文用法提示返回，未预期异常转为命令错误并保持 CLI 可用。
- N6：状态输出必须稳定、可扫描，并对 secret 做与现有 `/config`、`/memory` 一致的脱敏。
- N7：补全不能依赖 LLM、网络或文件扫描，候选必须在本地即时生成。
- N8：重构后现有 Agent、权限、上下文、记忆、MCP 和 Provider 测试不得回退。

## 非目标

- 不支持用户自定义命令或从配置文件动态注册命令。
- 不支持 Skill 系统注册命令。
- 不实现动态生成提示词或让模型决定命令内容。
- 不实现命令级权限规则；命令内部触发的既有工具或服务继续遵循原有边界。
- 不实现命令参数的动态文件、会话或模型补全。
- 不更换 Rich 或 prompt_toolkit，也不在本章引入全屏 Textual 界面。
- 不删除隐藏兼容入口；正式移除旧命令留给后续破坏性版本。

## 验收标准

- AC1：注册两个大小写不同但规范化后同名的命令、别名冲突或名称与别名冲突时，启动在进入输入循环前失败，并指出冲突来源。
- AC2：解析空输入返回空结果；`/StAtUs` 命中 `status`；`/review  Focus On API` 保留参数文本的大小写。
- AC3：未知 `/foo` 只显示“未知命令”和 `/help` 引导，Provider、Agent 和工具调用次数均为零。
- AC4：普通文本仍进入 Agent Loop；所有已注册斜杠命令都先经过分流器。
- AC5：命令处理测试只依赖假的界面控制器，不需要 Rich Console 或真实 prompt_toolkit 会话。
- AC6：帮助默认只显示十个可见高频命令，隐藏兼容命令不出现；`/help review` 能显示用法和参数提示。
- AC7：补全候选来自注册中心，隐藏命令不出现，大小写不敏感；单候选和多候选路径都有测试。
- AC8：启动提示显示 `[DEFAULT]`；`/plan` 后显示 `[PLAN]` 且普通请求使用 Plan Mode；`/do` 后恢复 `[DEFAULT]` 且不自动调用 Provider。
- AC9：`/compact`、`/clear`、`/session`、`/memory`、`/permission`、`/status` 均不进入 Agent Loop；参数错误也不进入 Agent Loop。
- AC10：`/session` 能列出会话、恢复指定 ID、清理过期会话；隐藏 `/sessions` 和 `/resume <id>` 保持兼容。
- AC11：`/memory` 能显示状态并执行 update/rebuild；记忆禁用时返回清楚提示。
- AC12：`/permission` 能显示和切换 strict/default/permissive，隐藏 `/permissions`、`/perm` 行为一致，状态标记立即刷新。
- AC13：`/status` 同时展示模式、Provider、上下文/Token、权限、MCP 和记忆摘要，输出不含 API key 或认证 secret。
- AC14：`/review` 会向 Agent 发送固定审查提示词；可选 focus 被追加；会话历史记录的是展开后的提示词，并沿用当前模式。
- AC15：`/do` 不再执行最近计划；旧的一次性 `do` Prompt 注入路径不再由命令触发。
- AC16：`/exit` 和 `/quit` 能关闭 MCP、MemoryManager 和 session recorder；重复关闭不报错。
- AC17：完整单元测试、Python 编译检查和 `git diff --check` 通过；可用环境下按 `AGENT.md` 执行 tmux 端到端验收。
- AC18：README、验收清单和验收报告与十个可见命令及隐藏兼容策略一致。
