# HuiCode Memory System Spec

## Background

HuiCode 目前已经具备多轮对话、工具调用、Agent Loop、权限系统、MCP 工具接入、系统提示模块化和上下文压缩能力。当前会话里的消息可以被模型使用，但新会话启动后，项目知识、用户偏好、历史工作状态和纠正反馈不会自动恢复；用户需要反复说明项目约定、个人偏好和上次做到了哪里。

本章目标是为 HuiCode 加入记忆系统，让它在新会话启动时自动恢复项目指令、历史会话线索和长期笔记，并在每轮任务自然结束后持续沉淀新的偏好与项目知识。记忆系统必须和现有上下文管理协作：注入的信息要短、可控、可解释，不能挤爆上下文，也不能把摘要或笔记当成未经验证的文件事实。

## Goals

- 新会话启动后，HuiCode 能自动加载用户级和项目级指令，减少重复说明。
- 会话历史可以可靠落盘，并能在中断、坏行或部分损坏时尽量恢复可用部分。
- 任务自然结束后，HuiCode 能自动整理长期笔记，逐渐学习用户偏好、纠正反馈、项目知识和参考资料。
- 请求模型前注入精简记忆索引，让模型像已经读过关键项目背景一样工作。
- 记忆恢复、注入和更新过程必须受项目边界、上下文预算和安全规则约束。

## Functional Requirements

- F1: HuiCode 启动时必须自动加载项目指令文件，支持用户级与项目级来源；项目级指令优先级高于用户级，高优先级内容必须排在更靠前的位置。
- F2: 项目指令文件必须支持引用其他指令文件，并限制引用深度，防止循环引用。
- F3: 项目指令引用不得逃出允许的目录边界；当引用路径非法、过深或循环时，HuiCode 必须跳过危险引用并给出可诊断信息。
- F4: 项目指令内容必须作为系统级补充上下文注入，而不是伪装成用户输入。
- F5: HuiCode 必须把会话消息追加写入项目会话存档，保证正常崩溃时最多只影响最后一条记录。
- F6: 会话列表、会话标题和消息数量必须能从会话存档本身恢复出来，不依赖单独的同步状态文件。
- F7: 会话恢复时必须跳过坏行，并在遇到工具调用和工具结果不匹配时截断到最后一个协议安全边界。
- F8: 恢复会话时如果上下文预计超限，HuiCode 必须先尝试执行一次上下文压缩，再继续进入可交互状态。
- F9: 恢复很久以前的会话时，HuiCode 必须插入一条时间跨度提醒，让模型知道上下文存在时间间隔。
- F10: HuiCode 必须定期清理超过 30 天的过期会话存档，且清理不能影响当前活动会话。
- F11: 自动笔记必须分为用户偏好、纠正反馈、项目知识和参考资料四类。
- F12: 每轮 Agent Loop 自然结束且最终回复不再请求工具时，HuiCode 必须异步更新自动笔记；工具调用中断、API 错误、用户取消或达到停止上限时不得把未完成状态写成长期记忆。
- F13: 自动笔记更新必须交给模型判断是否新增、合并、删除或保持不变，避免简单重复堆积。
- F14: 用户级笔记和项目级笔记必须分开保存；项目知识默认进入项目级，跨项目偏好默认进入用户级。
- F15: HuiCode 必须维护一份精简记忆索引，并在处理用户请求前注入；索引要控制在可预测大小内。
- F16: 记忆索引必须包含足够定位原始笔记的信息；当模型需要细节时，应能通过文件工具重新读取，而不是凭索引臆测。
- F17: 记忆注入不得泄露 API key、认证 header、MCP secret、环境变量 secret 或权限配置中的敏感值。
- F18: 用户必须能通过 TUI 命令查看记忆状态、手动触发记忆整理、列出会话存档，并恢复指定会话。
- F19: `/clear` 只清空当前交互上下文，不删除长期笔记和会话存档；删除或清理长期记忆必须使用明确命令。
- F20: 记忆系统必须能和 Plan Mode、权限系统、MCP 工具、上下文压缩和现有系统提示模块同时工作，不破坏工具调用历史和 provider 协议要求。
- F21: 当记忆加载或更新失败时，HuiCode 必须继续可用，并把失败作为状态或警告展示，而不是让整个 Agent 崩溃。
- F22: README 必须说明指令文件、会话存档、自动笔记、索引、常用命令和边界限制。

## Non-Functional Requirements

- N1: 记忆文件必须存放在用户目录或项目 workspace 内，不得写入未授权路径。
- N2: 项目指令引用和会话恢复必须优先保证安全与协议合法性，不能为了恢复更多历史而破坏工具调用序列。
- N3: 记忆索引默认不超过 200 行或 25KB，避免长期记忆侵占主要上下文。
- N4: 自动笔记更新必须在主回复完成后进行，不能明显阻塞用户看到最终回答。
- N5: 会话存档和笔记更新必须使用稳定、可人工查看和可手动修复的文本格式。
- N6: 所有面向用户的命令输出和错误提示使用中文，且不得打印 secret 内容。
- N7: 如果自动记忆模型调用失败，最多影响本轮记忆更新，不得回滚对话历史或工具执行结果。
- N8: 测试必须覆盖损坏存档、工具结果截断、指令 include 环路、索引大小控制和记忆更新失败等异常路径。

## Out of Scope

- 不实现向量数据库或语义检索。
- 不实现团队共享记忆或远端同步。
- 不实现 MCP resources、prompts、sampling 等非工具能力。
- 不实现独立的记忆可视化 UI，只提供 TUI 命令和文本状态。
- 不把会话存档作为审计日志或安全审计系统。
- 不实现复杂的隐私分级、加密存储或云端备份。
- 不让模型在自动记忆更新阶段调用工具。
- 不要求精确 tokenizer；索引和恢复预算沿用现有近似估算策略。

## Acceptance Criteria

- AC1: 当用户级和项目级指令同时存在时，新请求发送给模型的系统上下文包含两者，且项目级内容排在用户级之前。
- AC2: 指令文件引用正常文件时会展开；引用循环、过深或逃逸路径时不会无限递归，也不会读取 workspace 外的非法文件。
- AC3: 新会话产生的用户消息、助手消息、工具调用和工具结果会被追加写入会话存档；进程异常结束后，重新扫描存档能恢复完整行。
- AC4: 会话列表中的 ID、标题、更新时间和消息数量来自存档扫描结果，而不是来自单独 meta 文件。
- AC5: 恢复含坏行的会话时，坏行被跳过并产生警告，可用消息仍能恢复。
- AC6: 恢复含未配对工具调用的会话时，历史会被截断到最后一个安全边界，后续请求不会触发 provider 的工具结果配对错误。
- AC7: 恢复超预算会话时，会先触发一次上下文压缩；压缩失败时仍保留可恢复的原始历史并提示风险。
- AC8: 恢复距离当前超过配置阈值的会话时，后续模型上下文中包含时间跨度提醒。
- AC9: 超过 30 天且不是当前活动会话的存档会被清理，当前会话不会被误删。
- AC10: 最终回复自然结束后，自动记忆更新会生成或更新四类笔记之一；错误结束、取消或达到上限时不会写入新长期笔记。
- AC11: 自动记忆更新不会重复写入明显相同的偏好或项目知识；当模型判断无需更新时，笔记文件保持不变。
- AC12: 用户级笔记和项目级笔记分别落到对应位置；项目级笔记不会写到用户级目录，用户偏好不会误写进项目知识文件。
- AC13: 记忆索引超过 200 行或 25KB 时会被压缩或重建到限制内。
- AC14: 处理普通请求前，模型上下文包含记忆索引和项目指令；索引内容带有原始笔记定位提示。
- AC15: `/memory` 或等价命令可以展示记忆状态、索引大小、笔记数量、最近更新时间和最近错误，且不泄露 secret。
- AC16: 会话相关命令可以列出、恢复和清理会话；恢复后继续提问时，模型能利用恢复的历史。
- AC17: `/clear` 后当前消息历史为空，但会话存档和长期笔记仍存在。
- AC18: 当指令加载、会话恢复或自动笔记更新失败时，HuiCode 仍能继续聊天，并给出中文警告。
- AC19: OpenAI 和 Anthropic 请求序列在注入项目指令、记忆索引、恢复历史和压缩边界后仍满足各自 provider 的消息格式要求。
- AC20: README 包含记忆系统的配置位置、文件格式、TUI 命令、自动记忆行为和限制说明。
- AC21: 自动化测试覆盖指令加载、会话存档/恢复、坏行跳过、工具安全截断、自动笔记更新、索引大小限制、TUI 命令和 provider 序列兼容。
