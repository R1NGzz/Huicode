# HuiCode Hook 系统 Spec

## 背景

HuiCode 已具备 Agent Loop、工具与权限系统、动态系统提示、上下文管理、记忆、Slash Command 和 Skill，但格式化、外部通知、额外安全校验和按事件补充上下文仍需要用户手动触发。此类工作通常有明确的触发时刻、固定条件和确定动作，不适合每次都交给模型临时决定。

本章要引入声明式 Hook 系统。用户通过 YAML 定义“事件 + 条件 + 动作”，HuiCode 在生命周期关键节点发布标准事件，由 Hook 匹配条件并执行固定动作。工具执行前 Hook 可以明确拒绝某次调用，并把拒绝原因作为普通工具结果回灌 Agent Loop；Hook 自身超时、异常或外部服务失败则只留下日志，不得拖垮主流程。

## 目标

- 用统一、可校验的声明格式管理生命周期自动化。
- 覆盖会话、轮次、消息、工具和少量系统级事件。
- 支持工具执行前的细粒度拦截，并允许模型根据拒绝结果调整方案。
- 支持命令、提示词、HTTP 和子 Agent 四类动作，其中子 Agent 本章只建立兼容占位。
- 支持单次、异步和超时控制，同时保证拦截事件的决定是同步且确定的。
- 隔离 Hook 运行故障与 Agent 主流程，并提供足够的诊断信息。

## 配置来源与覆盖

Hook 规则按以下顺序加载，后者优先级更高：

1. 用户级默认：`~/.huicode/hooks.yaml`
2. 本次启动配置：用户通过 `--config` 指定的 YAML 中的 `hooks`
3. 项目级覆盖：`<workspace>/.huicode/hooks.yaml`

每条规则必须有非空且在当前来源内唯一的 `id`。不同来源出现相同 `id` 时，高优先级规则整体替换低优先级规则；不同 `id` 的规则合并保留。规则可通过 `enabled: false` 停用，但仍必须保留合法的 event、action 和其他字段，确保重新启用时定义完整。

启动时对合并后的全部规则集中校验。未知事件、未知动作、非法条件、重复 id、无效超时、拦截事件异步执行、缺失动作字段或不兼容的事件与动作都视为配置错误，HuiCode 应指出来源文件、规则 id 和具体字段并停止启动。运行期动作失败不属于配置错误。

基础格式：

```yaml
hooks:
  - id: format-python-after-edit
    event: tool_after
    if:
      all:
        - field: tool.name
          exact: Edit
        - field: tool.arguments.path
          glob: "**/*.py"
    action:
      type: command
      command: python
      args:
        - .huicode/hooks/format_python.py
    once: false
    async: true
    timeout_seconds: 30
```

`if` 可省略，表示该事件每次发生都触发。`once`、`async` 和 `timeout_seconds` 均可省略并使用安全默认值。

## 生命周期事件

### 会话级

- `session_start`：Hook 配置、工具、权限、记忆和 Skill 初始化完成后，第一次用户输入前触发。
- `session_end`：正常退出或输入结束后、资源关闭前触发；异常退出尽力触发，但不保证进程被强制终止时执行。

### 轮次级

- `turn_start`：普通用户输入已通过 Slash Command 分流、即将进入 Agent Loop 时触发。
- `turn_end`：本轮因最终回答、取消、错误、未知工具上限或最大迭代次数停止时触发，并携带停止原因。

### 消息级

- `message_received`：用户消息加入当前对话后、第一次模型请求前触发。
- `message_completed`：一次完整模型响应收集并写入历史后触发，载荷说明它是最终文本还是包含工具调用的中间响应。

### 工具级

- `tool_before`：工具名已解析、JSON 参数已拼接完成后，Plan Mode、权限确认和真实工具执行之前触发。
- `tool_after`：成功、失败、权限拒绝或 Hook 拒绝形成结构化工具结果后、结果回灌模型之前触发。

由 Hook 拒绝产生的工具结果仍会触发一次 `tool_after`，但不得再次触发 `tool_before`。事件载荷要标明结果来源，防止规则形成递归。

### 系统级

- `context_before_compact`：上下文管理器准备执行重量压缩前触发。
- `context_after_compact`：压缩成功、跳过或失败后触发，并携带结果摘要。
- `agent_error`：Provider、事件流或 Agent Loop 出现可报告错误时触发。

Hook 自身产生的错误不再发布 `agent_error`，只写 Hook 日志，避免错误处理递归。

## 标准事件载荷

所有事件至少提供：事件名、发生时间、会话 id、工作区、当前模式、当前轮次、规则可见的来源信息。不同层级再提供相应字段：

- 轮次：原始用户输入、迭代数、停止原因。
- 消息：角色、文本预览、是否包含 thinking、工具调用摘要。
- 工具：调用 id、工具名、完整结构化参数、目标摘要；`tool_after` 另含成功状态、错误码、结果摘要和结果来源。
- 上下文：触发原因、压缩前后估算和状态。
- 错误：错误类别和脱敏后的错误摘要。

认证密钥、完整请求头、Provider thinking 原文和未声明的进程环境变量不得进入 Hook 载荷或日志。大文本只提供有界预览和已有落盘路径，避免 Hook 复制整份上下文。

命令动作从标准输入接收 JSON 载荷；HTTP 动作以 JSON 请求体发送同一载荷。这样动作不需要依赖 TUI 文本，也不会通过拼接模型参数生成一条新的 shell 命令。

## 条件表达式

条件由若干叶子条件组成。每个叶子指定事件载荷字段，并且只能选择一种匹配方式：

- `exact`：完整字符串精确匹配。
- `glob`：使用与权限规则一致的大小写敏感 glob 匹配。
- `regex`：正则表达式搜索；无效正则在启动校验阶段报错。
- `not`：对一个合法的 exact、glob 或 regex 子条件取反。

工具条件复用权限系统对工具别名和主要目标参数的标准化规则，`Glob` 与 `Find` 等别名必须得到一致结果。字段不存在时，正向条件为不匹配，反向条件为匹配。

多个条件只能使用以下一种逻辑容器：

- `all`：全部叶子满足才触发。
- `any`：任一叶子满足就触发。

同一 `if` 中不得同时出现 `all` 和 `any`，本章不支持任意层级嵌套布尔表达式。无条件 Hook 省略整个 `if`。

## 工具执行前拦截

`tool_before` 是唯一允许阻止当前 Agent 动作的事件，且所有匹配规则必须同步、按合并后的声明顺序执行。任一规则返回明确拒绝后：

1. 停止执行剩余 `tool_before` 规则。
2. 不进入权限确认，也不运行目标工具。
3. 生成错误码稳定、包含规则 id 和拒绝原因的结构化工具结果。
4. 像普通工具失败一样写入对话历史并触发 `tool_after`。
5. Agent Loop 继续下一轮，让模型选择其他方案。

明确拒绝与 Hook 失败必须分开：

- 命令动作退出码 `2` 表示明确拒绝，标准错误中的有界文本作为原因。
- HTTP 动作返回成功状态并提供 `decision: deny` 与非空 `reason` 表示明确拒绝。
- 超时、网络错误、启动失败、其他非零退出码、无效响应或解析异常都属于 Hook 失败，只记日志并按“未拒绝”继续。

多个普通 Hook 不提供显式优先级字段；执行顺序只由合并后的确定性声明顺序决定。

## 动作类型

### 命令动作

- 必须声明可执行命令，可选参数、工作目录和附加环境变量。
- 默认工作目录为当前项目，工作目录必须位于项目沙箱内。
- 附加环境变量支持 `${VAR}` 展开；未定义变量在启动校验时报错。
- 标准输入接收事件 JSON，标准输出和错误被有界捕获并写入 Hook 日志。
- 配置中声明的固定命令不触发 Agent 工具权限确认，但仍受不可绕过的危险命令黑名单和路径沙箱约束。

### 提示词动作

- 必须声明非空提示词，并以带特殊标签的系统级补充指令注入，不能伪装成用户消息。
- 支持 `next_request`、`turn`、`session` 三种作用域，默认 `next_request`。
- `next_request` 在下一次 Provider 请求后移除；`turn` 在本轮结束后移除；`session` 在会话结束前持续存在。
- 提示词可以引用受限的事件字段占位符；未知字段在启动校验时报错，值按纯文本处理，不改变 Hook 配置结构。
- `session_end` 不允许提示词动作，因为之后不存在可消费该指令的模型请求。

### HTTP 动作

- 必须声明 URL，可选方法、请求头和期望状态范围；默认发送 JSON POST。
- URL、请求头值支持 `${VAR}` 展开，敏感请求头在日志中脱敏。
- 响应体只保留有界预览；非预期状态、连接错误和无效 JSON 按 Hook 失败处理。
- 本章不限制目标域名、请求速率或总网络配额，配置作者应把 Hook 配置视为可信代码。

### 子 Agent 动作

- YAML 可以声明 `subagent` 动作及任务文本，为后续 SubAgent 章节保留稳定配置形状。
- 本章触发时只记录“尚未实现”的 Hook 日志，不启动模型、不修改主历史，也不阻断 Agent。
- `tool_before` 不允许使用子 Agent 动作，以免形成无法及时返回的拦截决定。

## 执行控制

- `once: true` 表示同一规则在当前 HuiCode 进程内第一次匹配后只执行一次。是否成功执行不影响已运行标记；本章不跨重启持久化。
- `async: true` 表示动作提交后台后主流程立即继续。`tool_before`、提示词动作和任何需要立即消费返回值的动作禁止异步。
- `timeout_seconds` 控制单次命令或 HTTP 动作的最长运行时间；超时后终止或取消该动作并记录失败。
- 同步 Hook 按确定性声明顺序执行；后台 Hook 可以并发完成，完成顺序不作保证。
- 会话正常结束时，在有界等待时间内收拢后台任务并记录未完成项，不无限阻塞退出。

## 失败隔离与可观测性

- Hook 运行时异常、超时、非拦截失败和日志写入失败都不得改变 Agent Loop 的停止原因，不得让 TUI 崩溃。
- 每次 Hook 运行都记录时间、规则 id、事件、动作类型、耗时、状态和脱敏摘要；状态至少区分 success、denied、failed、timeout、skipped 和 scheduled。
- 日志采用追加写，单条日志损坏不影响后续记录；日志不得进入会话消息和 LLM 上下文。
- 启动时显示有效 Hook 数、禁用数和来源摘要。运行时默认不刷屏，只在配置错误时阻止启动；详细执行结果通过日志查看。
- 日志目录和落盘文件受项目沙箱约束，并有单条记录大小上限。

## 功能需求

- F1：系统必须从用户级、启动配置和项目级 YAML 加载 Hook，按 id 确定性覆盖并集中校验。
- F2：系统必须发布本规范定义的会话、轮次、消息、工具和系统级事件，并提供稳定、脱敏的标准载荷。
- F3：Hook 条件必须支持 exact、glob、regex、not，以及互斥的 all/any 组合；无 `if` 时无条件触发。
- F4：`tool_before` Hook 必须能明确拒绝工具调用，拒绝结果回灌模型且不中止 Agent Loop。
- F5：系统必须支持 command、prompt、http、subagent 四种动作；subagent 本章只记录占位状态。
- F6：提示词动作必须以系统级补充指令注入，并按 next_request、turn 或 session 作用域清理。
- F7：Hook 必须支持当前进程只运行一次、后台异步和动作超时，且拦截事件不得异步。
- F8：Hook 运行失败必须与主流程隔离，留下结构化、脱敏、追加式日志。
- F9：命令和 HTTP 动作必须接收统一事件 JSON，命令动作仍受不可绕过的命令黑名单和项目路径沙箱保护。
- F10：系统必须在启动时给出 Hook 加载摘要，并在退出时有界收拢后台动作。

## 非功能需求

- N1：未配置 Hook 时，Agent 行为、性能和现有测试结果应与本章前一致。
- N2：同步事件分发和条件匹配应保持轻量，不得引入新的 LLM 请求。
- N3：事件、条件和动作应通过统一扩展点增加，不能把 Hook 逻辑散落为不可复用的分支。
- N4：规则顺序、覆盖结果和条件匹配在相同配置与输入下必须可重复。
- N5：日志与错误信息不得泄露 API key、Authorization、Cookie 或完整 thinking 内容。
- N6：Windows 与常见 POSIX 环境都应能运行命令动作，并正确处理 UTF-8 事件载荷。

## 不在本章范围

- 子 Agent 动作的真实执行和结果回流。
- `once` 运行标记跨进程持久化。
- 用户自定义 Hook 显式优先级或依赖关系。
- Hook 配置热更新和运行中增删规则。
- HTTP 域名白名单、网络沙箱、速率限制、资源配额和重试策略。
- 图形化 Hook 编辑器、Hook 市场或远程规则分发。
- 让 LLM 自动生成、修改或批准 Hook 配置。

## 验收标准

- AC1（F1）：三层配置存在同 id 和不同 id 规则时，最终目录按“用户级 < 启动配置 < 项目级”得到确定结果；任一非法定义会在启动时指出规则 id、来源和字段。
- AC2（F2）：一次包含模型回复和工具调用的真实 Agent 轮次能观察到 session、turn、message、tool 对应事件；上下文压缩和请求错误能分别产生系统事件，载荷不含密钥和 thinking 原文。
- AC3（F3）：exact、glob、regex、not、all、any 和无条件规则都有正反匹配用例；all 与 any 混用或正则无效时启动失败。
- AC4（F4）：匹配的 `tool_before` 命令以退出码 2 拒绝写文件后，目标文件不改变、权限确认不出现、模型收到带规则 id 与原因的工具结果并能继续回答或改用其他方案。
- AC5（F5）：command 能收到事件 JSON 并执行；prompt 能影响模型的后续请求；HTTP 能收到相同 JSON；subagent 只记录 skipped/not-implemented 且不发起模型调用。
- AC6（F6）：next_request 指令只出现一次，turn 指令在本轮后消失，session 指令跨轮保留到退出；三者都以系统补充标签出现而非用户消息。
- AC7（F7）：once 规则同一进程只运行一次；后台规则不阻塞主流程；超时动作被终止并记为 timeout；异步 `tool_before` 在启动校验时被拒绝。
- AC8（F8）：命令不存在、HTTP 断连、无效响应和动作超时均只产生脱敏 Hook 日志，Agent 仍完成原任务且 TUI 不崩溃。
- AC9（F9）：命令与 HTTP 观察到结构一致的事件核心字段；危险命令和越界工作目录被 Hook 安全边界拒绝，且该拒绝作为 Hook 失败记录而不执行目标动作。
- AC10（F10）：启动输出能看到有效、禁用和来源数量；退出时后台任务只等待规定上限，不会无限卡住终端。
- AC11（N1-N6）：未配置 Hook 的回归测试、Hook 专项测试、UTF-8 命令载荷测试和完整端到端场景全部通过。
