# Agent Team 验收清单

> 实施完成后逐项填写实际结果。未提供证据的项目不得标记通过。

## 一、配置、命名与持久化

- [x] **C1 默认配置兼容**：旧版 `huicode.yaml` 不含 `teams` 时仍可启动，Team 能力使用安全默认值且默认关闭。
  **验证：** 配置单元测试加载最小旧配置并断言 `LLMConfig.teams`。对应 AC13。

- [x] **C2 完整 Team 配置可加载**：后端、成员上限、锁参数、轮询、关闭超时、Coordinator 和集成检查命令均能正确读取。
  **验证：** 完整 YAML fixture 逐字段断言。

- [x] **C3 错误配置前置失败**：非法后端、非正数、错误字段类型和非法检查命令在进入 TUI 前返回带字段名的中文错误。
  **验证：** 参数化配置测试并检查 CLI 退出码。

- [x] **C4 Coordinator 双锁判定正确**：仅配置、仅环境变量、两者都开、两者都关四种组合结果符合规格。
  **验证：** 隔离环境变量的参数化测试。对应 AC11。

- [x] **C5 团队与成员名安全**：合法名称可创建；路径逃逸、绝对路径、分隔符、保留名、控制字符、超长和重名在写盘前被拒绝。
  **验证：** 命名表驱动测试，Fake Store 写入次数为 0。对应 AC1。

- [x] **C6 团队快照原子可靠**：有效快照可往返；故障注入不会把半截临时文件当成有效团队状态。
  **验证：** 原子替换中断测试和格式版本测试。对应 AC1。

- [x] **C7 JSONL 损坏可恢复**：邮箱、事件或成员会话出现单条坏行时跳过并报告，其他有效记录仍可读取。
  **验证：** 在中间与末尾插入坏行后恢复。对应 AC6、AC8。

- [x] **C8 Team 重启恢复完整**：重建 TeamManager 后，团队 ID、负责人、花名册、任务、审批和持久化位置保持一致。
  **验证：** 使用同一临时 Team 根目录创建两次 Manager 并比较快照。对应 AC1。

## 二、成员后端与 Worktree

- [x] **C9 Auto 后端优先级固定**：能力可用时依次选择 tmux、Windows Terminal、协程。
  **验证：** 注入不同 availability 组合并断言 actual backend。对应 AC2。

- [x] **C10 显式 terminal 不降级**：tmux 与 Windows Terminal 都不可用时，显式 terminal 启动失败且协程 launch 未调用。
  **验证：** Fake Backend 调用计数。对应 AC2。

- [x] **C11 实际后端可观察**：成员启动记录和 TUI 事件都展示最终选中的后端，而不是只展示请求值。
  **验证：** Manager 事件与 TUI 渲染测试。对应 AC2、AC9。

- [x] **C12 终端命令不泄密**：tmux/wt 启动使用参数数组、`shell=False` 和显式 cwd，命令行不含 API Key。
  **验证：** mock `subprocess` 检查完整参数。

- [x] **C13 终端唤醒和停止定向**：tmux 只唤醒目标 pane；Windows 只触发目标 worker 事件；停止不会误伤其他成员。
  **验证：** 双成员 Fake Handle 测试。对应 AC6、AC9。

- [x] **C14 协程成员状态隔离**：两个成员的 Future、停止事件、唤醒事件、异常和运行状态互不串线。
  **验证：** 并发 Worker Pool 测试。对应 AC9。

- [x] **C15 所有成员都有 Worktree**：协程、终端、读写角色和只读角色均得到各自独立目录与分支。
  **验证：** 临时 Git 仓库创建四种成员并比较路径、分支。对应 AC3。

- [x] **C16 成员修改互不覆盖**：两个成员修改同名文件时只影响各自 Worktree，用户当前工作区保持原值。
  **验证：** 读取三处文件内容并比较。对应 AC3。

- [x] **C17 Worktree 失败不回退**：成员 Worktree 创建或恢复失败后标记失败，主工作区工具零调用。
  **验证：** Fake WorktreeService 抛错并检查 Tool Runner。对应 AC3、AC9。

- [x] **C18 全局 cwd 不变化**：团队创建、成员运行、恢复、集成和关闭前后的 `Path.cwd()` 一致。
  **验证：** 生命周期集成测试前后断言。

## 三、共享任务与邮箱

- [x] **C19 任务 CRUD 可用**：Lead 可创建、查询、更新和安全删除任务，字段与更新时间正确持久化。
  **验证：** SharedTaskStore CRUD 单元测试。对应 AC5。

- [x] **C20 依赖阻塞和解阻正确**：前置任务未完成时后续任务 blocked，前置完成后自动变为可认领。
  **验证：** 两级和三级依赖测试。对应 AC5。

- [x] **C21 非法依赖被拒绝**：不存在依赖、自依赖和循环依赖均不写入任务快照。
  **验证：** 依赖图参数化测试并比较写入前后文件。对应 AC5。

- [x] **C22 任务并发不覆盖**：两个成员用同一版本竞争认领或更新时只有一个成功，另一个收到结构化版本冲突。
  **验证：** 双线程屏障测试。对应 AC5。

- [x] **C23 任务删除有保护**：执行中的任务和被其他任务依赖的任务不能删除。
  **验证：** 两类删除拒绝测试。

- [x] **C24 点对点消息正确投递**：名称注册表解析目标后，消息只出现在目标邮箱且字段完整、默认未读。
  **验证：** 双成员邮箱测试。对应 AC6。

- [x] **C25 广播正确投递**：Lead 广播后每个当前成员各收到一条同 correlation ID 的消息，发件人和收件范围正确。
  **验证：** 三成员广播测试。对应 AC6。

- [x] **C26 邮箱锁可恢复**：活动锁按配置重试后失败，符合条件的过期锁被回收，并发追加不产生交错 JSON。
  **验证：** 锁竞争、过期锁和多线程追加测试。对应 AC6。

- [x] **C27 唤醒失败不丢消息**：backend wake 抛错时 ToolResult/事件包含警告，已落盘消息仍可读取。
  **验证：** Fake Backend 故障注入。对应 AC6、AC9。

- [x] **C28 协议消息严格配对**：计划、任务、进度、完成和 idle 消息保留 request/task ID；未知协议被隔离，不误触发控制动作。
  **验证：** 协议解析与坏 payload 测试。对应 AC6、AC7。

## 四、审批、工具作用域与 Coordinator

- [x] **C29 审批成员先申请计划**：需要审批的成员收到任务后进入 waiting_approval，并产生带唯一 request ID 的结构化计划申请。
  **验证：** Fake Provider 成员运行测试。对应 AC7。

- [x] **C30 未批准不能执行副作用**：等待审批时 Write、Edit、Bash 等副作用工具既不出现在 ToolSpec 中，伪造历史调用也返回审批拒绝。
  **验证：** Registry 枚举和 Agent Loop 直接调用双重测试。对应 AC7。

- [x] **C31 自然语言不能批准**：Lead 发送“批准”“可以”等普通文本后审批仍为 pending。
  **验证：** 邮箱写入普通消息后查询 ApprovalGate。对应 AC7。

- [x] **C32 结构化批准严格匹配**：只有成员、任务和 request ID 匹配的 allow 才开放副作用；过期、错配和重复决定无效。
  **验证：** 审批参数化测试。对应 AC7。

- [x] **C33 驳回可重新规划**：deny 反馈进入成员上下文，旧请求关闭，新计划使用新 request ID，再批准后可执行。
  **验证：** deny → replan → allow 端到端 Runner 测试。对应 AC7。

- [x] **C34 审批可跨重启恢复**：等待审批时重启成员或 Manager，成员仍等待同一请求且不能执行副作用。
  **验证：** 持久化恢复测试。对应 AC7、AC8。

- [x] **C35 四类工具作用域正确**：普通 main 仅见 Team 入口；Lead 见管理工具；成员只见任务/消息/计划申请；普通子 Agent 不见任何 Team 工具。
  **验证：** 四类 RuntimeIdentity 的 ToolSpec 与直接 get 测试。对应 AC4。

- [x] **C36 Team 成员不能无限派生**：团队成员无法发现或调用 Team 创建、成员派生、Lead 审批、集成和普通 Agent 派生工具。
  **验证：** 成员作用域未知工具结果测试。对应 AC4。

- [x] **C37 Coordinator 写工具被剥夺**：双锁开启后 Lead 不见 Write/Edit 等直接修改工具，状态栏显示 coordinator。
  **验证：** ToolSpec 与 TUI 状态测试。对应 AC11。

- [x] **C38 Coordinator Bash 不能绕过**：重定向、管道、shell 控制符、非 Git 命令和写文件 Git 用法被程序拒绝；允许的 Git 状态/合并诊断可运行。
  **验证：** 命令白名单参数化测试。对应 AC11。

- [x] **C39 Coordinator 仍能协调**：双锁开启后 Lead 仍可读取、派人、管理任务、发消息、审批、停止成员和调用集成工具。
  **验证：** Coordinator 完整工具列表和操作测试。对应 AC11。

## 五、成员生命周期与 Lead 编排

- [x] **C40 成员状态转换完整**：成员按 starting → working/waiting_approval → idle/failed/stopped 转换，非法倒退被拒绝。
  **验证：** 状态机单元测试。对应 AC1、AC9。

- [x] **C41 完成后进入 idle 并通知**：模型最终回复后任务结果持久化，成员变 idle，Lead 收到 completion 和 idle 事件。
  **验证：** Fake Provider 正常完成场景。对应 AC8。

- [x] **C42 空闲成员继续原上下文**：向 idle 成员派第二个任务时复用相同成员 ID、Worktree 和历史，不创建同名新成员。
  **验证：** 两轮任务中让第二轮引用第一轮唯一事实。对应 AC8。

- [x] **C43 后端释放后可恢复**：停止运行实例但保留团队后，再发消息能重启后端并恢复成员会话。
  **验证：** close/reopen Fake Backend 场景。对应 AC8。

- [x] **C44 损坏上下文不冒充恢复**：会话无法通过协议安全恢复时成员标记 failed 并通知 Lead，不从空历史执行任务。
  **验证：** 不可恢复 fixture 和 Provider 零调用断言。对应 AC8、AC9。

- [x] **C45 Lead 编排能力完整**：Lead 可创建依赖任务、分派或调整成员、查看状态、单发/广播、审批和停止成员。
  **验证：** Team 工具集成测试。对应 AC9。

- [x] **C46 单成员故障隔离**：一个成员 Provider、邮箱或后端失败时，其他成员和主 Agent 继续运行，Lead 收到关联错误。
  **验证：** 双成员故障注入测试。对应 AC9。

- [x] **C47 停止顺序正确**：停止成员时先调用 backend.stop，成功或明确超时后才持久化 stopped/failed 状态。
  **验证：** 带调用序列的 Fake Backend。对应 AC12。

## 六、集成、发布与删除保护

- [x] **C48 集成只接受已提交成果**：脏 Worktree、无成员提交、失败任务和未完成依赖不会进入自动集成。
  **验证：** 临时 Git 仓库参数化状态测试。对应 AC10。

- [x] **C49 依赖顺序合并**：多个成员分支按任务拓扑顺序合入专用 integration 分支，不在用户当前分支直接逐个 merge。
  **验证：** 检查集成日志父子顺序和主分支 ref。对应 AC10。

- [x] **C50 发布前用户工作区不变**：成员合并和 integration checks 期间，用户当前工作区文件、索引和 HEAD 均保持不变。
  **验证：** 集成各阶段前后记录文件摘要、`git status` 和 HEAD。对应 AC10。

- [x] **C51 Resolver 独占且可继续**：冲突时只有 resolver 可进入集成 Worktree；解决并提交后可继续合并和验证。
  **验证：** 冲突仓库与租约竞争测试。对应 AC10。

- [x] **C52 冲突或验证失败安全中止**：无法解决冲突或检查失败时只回滚专用集成状态，原目标分支和用户工作区不变。
  **验证：** 冲突失败与检查退出非零场景。对应 AC10。

- [x] **C53 目标漂移拒绝发布**：团队运行期间目标分支新增提交后，旧集成结果不能覆盖或直接发布。
  **验证：** 发布前移动目标 ref 并断言返回 target_changed。对应 AC10。

- [x] **C54 成功发布受控**：目标未变化且工作树安全时，验证通过的 integration 结果以 fast-forward 发布，未验证结果不能发布。
  **验证：** 临时仓库比较发布前后 ref 和完整文件内容。对应 AC10。

- [x] **C55 删除保护完整**：活动成员、未完成任务、未读消息、待审批、未发布集成、脏或含未集成提交的 Worktree 任一存在时拒绝删除并列出原因。
  **验证：** 每种保护条件独立测试。对应 AC12。

- [x] **C56 关闭不等于删除**：关闭团队只停止后端并保留团队、邮箱、会话、分支和 Worktree，之后仍可恢复。
  **验证：** close → 新 Manager → resume 场景。对应 AC1、AC12。

- [x] **C57 清理故障不影响其他团队**：一个团队的后端或 Worktree 删除失败时，另一个团队目录和状态不变。
  **验证：** 双团队故障注入测试。对应 AC12。

## 七、端到端、文档与回归

- [x] **C58 双成员完整端到端通过**：在临时 Git 仓库中创建 Team，两个协程成员在独立 Worktree 完成依赖任务、互发消息，其中一人经历 deny/replan/allow，完成后 idle，再恢复执行第二个任务，最后在集成 Worktree 验证并发布。

- [x] **C61 TUI 状态和异步事件可读**：状态栏显示 Team/Lead/Coordinator，成员启动、审批、消息、idle、恢复和集成事件不会破坏当前输入行。
  **验证：** Fake PromptSession 渲染测试和 CLI 输出快照。对应 AC2、AC9、AC11。

- [x] **C62 README 示例有效**：文档 YAML 可被真实解析器加载，工具名和参数与实际 Schema 一致。

- [x] **C63 Team 专项测试通过**：所有 Team 配置、存储、任务、邮箱、审批、后端、Worktree、作用域、Runner、集成、Manager、工具和 CLI 测试通过。

- [x] **C64 全量测试通过**：现有聊天、Provider、工具、权限、MCP、上下文、记忆、Slash Command、Skill、Hook、子 Agent 和 Worktree 无回归。

  **验证：** `python -m compileall huicode tests`。

- [x] **C66 Diff 检查通过**：不存在尾随空格、冲突标记或空白错误。
