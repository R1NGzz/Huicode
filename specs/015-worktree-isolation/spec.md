# Worktree 隔离需求规格

## 背景

HuiCode 已支持定义式子 Agent 与 Fork 子 Agent，但子 Agent 当前仍在主工作区内执行文件操作。主 Agent 与多个子 Agent 并行修改同一仓库时，可能互相覆盖文件、读取到对方尚未完成的状态，或污染主工作区。

本章为定义式子 Agent 增加基于 Git 多工作目录的隔离能力。需要隔离的子 Agent 在独立目录和独立分支中工作，同时继续复用同一 Git 仓库。Fork 子 Agent保持现有行为，继续共享主工作区。

## 目标

- 为声明隔离需求的定义式子 Agent 自动创建并使用独立工作目录。
- 让主 Agent 与隔离子 Agent 可以同时修改仓库而不直接覆盖彼此文件。
- 提供可恢复、可退出、可安全删除的完整工作目录生命周期。
- 初始化隔离目录所需的本地配置、Hooks、依赖和忽略文件。
- 对目录名、恢复和清理操作建立严格的安全保护。
- 保证工具、缓存、项目指令和记忆始终按实际工作目录隔离。

## 功能需求

### F1 隔离声明与适用范围

- 定义式子 Agent 的角色定义可声明 `isolation: worktree`。
- 未声明隔离或使用默认值的定义式子 Agent 继续使用主工作区。
- Fork 子 Agent 不启用 Worktree 隔离，继续共享主工作区。
- 非法的隔离类型应在角色加载时给出明确错误，不得延迟到任务运行阶段。

### F2 独立工作目录与分支

- 每个隔离任务使用 Git 原生多工作目录能力获得独立目录和独立分支。
- 隔离目录位于当前仓库内部的专用、不被版本控制追踪的位置。
- 隔离任务以任务启动时主仓库的当前 `HEAD` 为基线。
- 主工作区中未提交的修改不得自动带入隔离目录。
- 不同隔离任务不得共享可写工作目录或工作分支。

### F3 安全名称与路径

- 工作目录的逻辑名称必须限制允许字符、路径段长度、总长度和嵌套深度。
- 名称允许使用正斜杠表达受控的嵌套目录。
- 空路径段、`.`、`..`、绝对路径、盘符、反斜杠以及其他可能造成路径逃逸的形式必须被拒绝。
- 最终解析路径必须位于专用 Worktree 根目录内。
- 非法名称应在执行任何 Git 或文件写入操作前失败，并返回可理解的原因。

### F4 生命周期管理

- 系统应支持创建、进入、退出和删除隔离工作目录。
- “进入”和“退出”只改变目标任务使用的工作目录，不得改变 HuiCode 进程的全局当前目录。
- 创建时若目标目录不存在，应创建新的 Worktree、分支和管理信息。
- 创建时若目标目录已存在，只允许执行只读文件系统检查，不得调用 Git 修改或探测命令。
- 已存在目录仅在 HuiCode 管理清单中的仓库标识、任务标识和目标路径全部匹配时才允许快速恢复。
- 管理清单缺失、损坏或不匹配时必须拒绝接管该目录。
- 重复退出应保持幂等，不得破坏其他任务状态。

### F5 环境初始化

- 新建隔离目录后，应按配置规则复制本地配置文件。
- 应为隔离目录配置项目所需的 Git Hooks。
- 应按配置规则为大型依赖目录建立共享链接，避免不必要的重复复制。
- 应按配置规则补回被 Git 忽略但运行所需的文件。
- 环境初始化失败时应报告具体步骤和原因，不得让子 Agent 在半初始化状态下继续执行。
- 恢复已有隔离目录时不得重复执行可能覆盖用户修改的初始化动作。

### F6 显式工作目录传递

- 所有子 Agent 工具调用必须显式使用该任务绑定的工作目录。
- 系统不得依赖进程级目录切换来实现隔离。
- 相对路径必须相对于任务绑定的工作目录解析。
- 文件内容缓存、系统提示、项目指令和记忆等路径相关状态不得跨工作目录错误复用。
- 隔离子 Agent 的上下文中应明确告知其工作目录和独立分支状态。

### F7 子 Agent 生命周期集成

- 声明 Worktree 隔离的定义式子 Agent 启动前必须先完成隔离目录准备。
- 子 Agent 运行时的文件读取、写入、搜索和命令执行都必须落在隔离目录中。
- 隔离准备失败时，任务应以清楚的失败状态结束，不得退回主工作区继续执行。
- 子 Agent 完成后，系统应检查任务结果和目录变更，再决定自动删除或保留。
- 主 Agent 收到的任务结果应包含隔离目录、分支和保留状态，便于后续检查或合并。

### F8 变更与提交保护

- 成功结束且工作目录干净的隔离任务可以自动删除。
- 存在未提交修改、未推送提交、任务失败或任务取消时必须保留隔离目录。
- 默认删除操作遇到未提交修改或未推送提交时必须拒绝，不得静默丢弃成果。
- 对已有上游的分支，应识别尚未推送的提交；没有上游的任务分支只要产生了基线之后的提交，也应视为未推送。
- 强制删除不属于本章的默认自动流程。

### F9 过期目录清理

- 系统应支持后台定期发现超过配置期限的临时隔离目录。
- 清理候选必须同时通过专用根目录边界、有效管理清单和仓库归属校验。
- 后台清理必须复用未提交修改和未推送提交保护，不得绕过删除规则。
- 不满足全部安全条件的目录应跳过并记录原因，且不得影响 Agent 主流程。
- 过期清理失败不得中断正常对话或其他子 Agent 任务。

### F10 配置与可诊断性

- 用户可配置 Worktree 根目录、过期期限、复制规则、共享链接规则、忽略文件恢复规则和 Hooks 来源。
- 默认配置应在没有额外规则时仍可安全创建和运行基础 Worktree。
- 创建、恢复、保留、删除和清理跳过等关键状态应通过子 Agent 事件或结果向界面提供可展示信息。
- Git 不可用、当前目录不是仓库、目标分支冲突或平台不支持链接时，应返回明确且可操作的错误。

## 非功能需求

### N1 安全性

- 所有由模型或配置提供的目录名和路径都必须在使用前验证并规范化。
- 任何自动恢复或删除行为都应采取默认拒绝策略，不能仅凭目录存在或名称相似执行。

### N2 隔离性

- 并行任务的文件状态、路径缓存、权限跟踪和 Token 统计不得串线。
- Worktree 管理不得修改主进程全局工作目录。

### N3 可靠性

- 生命周期操作应尽可能幂等；中断后可根据可信管理信息恢复。
- 单个 Worktree 的创建、初始化或清理失败不得破坏其他 Worktree 或主工作区。

### N4 可移植性

- Windows、Linux 和 macOS 上应遵循一致的安全语义。
- 对符号链接或目录链接能力差异应显式报错或使用经过配置允许的兼容行为，不得静默复制后伪装成链接成功。

### N5 可测试性

- Git 操作、文件初始化、恢复判定和清理判定应可在临时仓库中独立验证。
- 测试不得依赖用户真实仓库、真实远端或全局 Git 配置。

## 不在本章范围

- Worktree 分支与主分支之间的自动合并、变基或冲突解决。
- 不同 Worktree 之间的实时文件同步。
- Fork 子 Agent 的 Worktree 隔离。
- 多 Agent 团队编排、任务依赖图和并行调度策略。
- 强制删除脏目录或未推送提交的交互式覆盖流程。
- 子 Agent 后台任务的跨会话持久化。

## 验收标准

### AC1 隔离创建

给定一个声明 `isolation: worktree` 的定义式子 Agent，启动任务后会从主仓库当前 `HEAD` 创建独立目录和分支；主工作区未提交修改不出现在该目录中，主工作区文件也不会被子 Agent 的修改直接覆盖。（覆盖 F1、F2、F7）

### AC2 默认与 Fork 行为

未声明隔离的定义式子 Agent 和 Fork 子 Agent 继续使用主工作区；非法隔离值在角色加载阶段失败。（覆盖 F1）

### AC3 路径安全

合法的嵌套名称可在专用根目录下创建；包含路径逃逸、绝对路径、非法路径段或超限内容的名称在任何 Git 或写操作前被拒绝。（覆盖 F3）

### AC4 安全恢复

目标目录已存在且管理清单完全匹配时，只通过文件系统读取完成恢复；清单缺失、损坏或任一标识不匹配时拒绝接管，恢复路径不调用 Git。（覆盖 F4）

### AC5 环境可用

新建目录能按规则完成本地配置复制、Hooks 配置、依赖链接和忽略文件恢复；任一步失败时任务不会进入 Agent 执行阶段，恢复已有目录不会覆盖已有文件。（覆盖 F5）

### AC6 工具与上下文隔离

并行运行主 Agent 和至少两个隔离子 Agent 时，各自的相对路径、工具命令、文件缓存、项目指令和记忆均对应自身绝对工作目录，且进程全局当前目录保持不变。（覆盖 F6、F7，验证 N2）

### AC7 完成与保留

成功且干净的任务可自动清理；有未提交修改、未推送提交、失败或取消的任务会被保留，结果中能看到目录、分支和保留原因。（覆盖 F7、F8）

### AC8 删除保护

删除脏目录、含未推送提交的目录或无有效管理清单的目录时默认拒绝；没有上游但产生新提交的任务分支同样受到保护。（覆盖 F8，验证 N1）

### AC9 过期清理

过期清理只处理位于专用根目录、管理清单有效、仓库归属正确且无受保护变更的目录；其他目录被跳过并记录原因，清理失败不影响主流程。（覆盖 F9）

### AC10 配置与错误反馈

Worktree 初始化规则和过期期限可配置；在非 Git 仓库、Git 不可用、分支冲突和链接能力不满足时，用户能收到具体错误而不是子 Agent 静默退回主工作区。（覆盖 F10，验证 N3、N4）

### AC11 回归验证

现有聊天、工具、权限、Hook、Skill、Slash Command、记忆、上下文管理以及非隔离子 Agent 测试继续通过。（验证 N3）
