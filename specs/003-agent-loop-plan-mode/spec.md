# HuiCode Agent Loop 与 Plan Mode 规格说明

## 背景
HuiCode 当前已经具备终端对话、流式输出、工具系统、工具结果回灌和一次工具调用回合能力。实际使用中，模型经常需要多步完成任务：先查看文件，再搜索代码，再读取细节，最后修改或执行命令。当前“一次工具调用后就停”的行为会导致用户必须不断催促，也会让模型的后续工具调用意图泄漏成普通文本。

本阶段要把 HuiCode 升级为具备 ReAct 风格循环的 Agent：它可以在一次用户请求中多轮调用模型、执行工具、观察结果并继续调整，直到模型给出最终回答或触发安全停止条件。同时引入 Plan Mode：用户可以先让模型只用读类工具做计划，再用 `/do` 切换到全工具执行。

## 目标
- 让 HuiCode 在一次用户请求中自主循环调用工具，直到任务完成。
- 让循环具备明确停止条件，避免无限执行。
- 让 Agent 与 TUI 通过异步事件流解耦，界面只消费事件并展示。
- 让流式文本实时显示，同时完整收集模型响应用于历史记录和后续判断。
- 让一次返回多个工具调用时能按安全性分批执行：可并发的读类工具并发，有副作用工具串行。
- 支持 `/plan` 和 `/do` 两段式工作流：先只允许读类工具产出计划，再允许全工具执行。
- 保持已有工具系统、DeepSeek Anthropic 兼容 thinking 回传、Claude Code 风格工具行继续可用。

## 功能需求
- F1: HuiCode 应支持 ReAct 风格循环：模型请求工具后，HuiCode 执行工具、回灌结果，并继续请求模型，直到模型不再请求工具。
- F2: 一次用户请求中可以发生多轮模型调用和多轮工具执行。
- F3: 当模型输出最终文本且不再请求工具时，Agent Loop 应正常结束。
- F4: Agent Loop 应有迭代上限作为兜底安全网，达到上限时停止并提示用户。
- F5: 用户取消当前任务时，Agent Loop 应停止，并保留已完成的可见输出和历史状态。
- F6: 连续请求未知工具达到限制时，Agent Loop 应停止，并提示未知工具问题。
- F7: 模型流式响应或 Provider 请求出错时，Agent Loop 应停止，并显示可读错误。
- F8: Agent 与界面之间应通过事件流传递状态，事件至少覆盖文本、thinking、工具调用、工具结果、进度、Token 用量和错误。
- F9: TUI 应基于事件流渲染，而不是直接耦合 Agent 内部执行过程。
- F10: 模型文本应边流式产生边展示给用户。
- F11: 同一段流式文本也应被完整收集，用于写入对话历史和判断是否继续循环。
- F12: 工具调用和工具结果应继续回灌进会话历史，使模型能基于前序观察继续行动。
- F13: 如果一次模型响应包含多个工具调用，HuiCode 应能识别并处理多个调用。
- F14: 多个读类工具调用可以并发执行，并分别展示工具行和结果摘要。
- F15: 有副作用的工具调用应串行执行，避免并发写文件、改文件或执行命令造成混乱。
- F16: 当同一批工具调用同时包含读类和副作用工具时，HuiCode 应按安全策略分批执行。
- F17: `/plan` 应进入 Plan Mode；Plan Mode 下模型只能使用读类工具分析项目并产出计划。
- F18: Plan Mode 下不得执行写文件、改文件、执行命令等副作用工具。
- F19: Plan Mode 的输出应让用户能看懂下一步准备做什么。
- F20: `/do` 应退出 Plan Mode 并进入执行模式；执行模式允许使用全部已注册工具。
- F21: `/do` 后，HuiCode 应能基于最近的计划和用户目标继续执行，而不是丢失计划上下文。
- F22: `/clear` 应清空对话历史、当前计划状态和循环状态。
- F23: 现有普通聊天、工具行展示、工具结果摘要和 workspace 边界应继续有效。
- F24: DeepSeek Anthropic 兼容 thinking 回传在多轮 Agent Loop 中仍应正确保留。
- F25: Agent Loop 不应实现权限系统、上下文压缩或用户交互式确认。

## 非功能需求
- N1: 项目继续遵循 AGENT.md：使用 Python，实现说明和代码注释使用中文。
- N2: Agent Loop 默认应有保守迭代上限，防止无限循环。
- N3: 事件流应便于后续接入更复杂 TUI、日志、追踪或测试。
- N4: 并发工具执行不得破坏 workspace 路径边界和现有工具错误结构。
- N5: 错误和停止原因应可读，用户能知道是完成、取消、上限、未知工具还是流错误。
- N6: 新能力应有单元测试覆盖，并在开发完成后对照 checklist.md 做端到端验收。
- N7: API key 等敏感信息不得出现在普通输出、事件或错误摘要中。

## 范围外
- 权限系统或用户逐工具确认。
- 上下文压缩、摘要记忆或长上下文管理。
- 用户在工具执行中途进行交互式选择。
- 自动 Git 提交、分支、PR 管理。
- 工具沙箱、容器隔离或系统级权限控制。
- 复杂任务调度器或长期后台任务。
- 图形化 TUI、多窗格 UI 或鼠标交互。

## 验收标准
- AC1: 对一个需要多步读取/搜索的问题，HuiCode 能在一次用户请求中执行多轮工具调用并最终回答。
- AC2: 当模型不再请求工具并输出最终文本时，Agent Loop 正常结束。
- AC3: 达到迭代上限时，HuiCode 停止循环并显示上限提示。
- AC4: 用户取消当前任务时，HuiCode 停止循环并回到可输入状态。
- AC5: 连续未知工具调用达到限制时，HuiCode 停止并显示未知工具提示。
- AC6: Provider 流式错误会停止循环并显示可读错误。
- AC7: TUI 能接收并展示文本、工具调用、工具结果、进度和错误事件。
- AC8: 文本能实时流式显示，同时完整写入会话历史。
- AC9: 工具调用与工具结果会在每一轮回灌进历史，下一轮模型请求能看到前序观察。
- AC10: 一次模型响应中多个读类工具调用可以被同一批处理，并都产生工具行和结果摘要。
- AC11: 多个副作用工具调用按顺序串行执行。
- AC12: 读类工具和副作用工具混合出现时，HuiCode 按安全分批策略执行。
- AC13: `/plan` 后请求任务时，只允许读类工具，计划阶段不会写文件、改文件或执行命令。
- AC14: Plan Mode 能产出可读计划。
- AC15: `/do` 后切换到全工具执行，并能利用最近计划继续完成任务。
- AC16: `/clear` 会清空历史和计划状态。
- AC17: 普通无需工具的问题仍能正常流式回答。
- AC18: Claude Code 风格工具行和结果摘要在循环多轮中持续显示。
- AC19: DeepSeek Anthropic 兼容 thinking 在多轮工具循环中不会因为未回传而触发 400。
- AC20: 新能力通过单元测试和编译检查。
