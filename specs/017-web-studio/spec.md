# HuiCode Studio Web 化与任务平台 Spec

## Background

HuiCode 当前已经具备较完整的 AI 编程 Agent 能力，包括流式对话、工具调用、权限控制、上下文管理、记忆、MCP、Skill、子 Agent、Agent Team、Hook 和 Worktree。但主要交互入口仍是本地 CLI，运行状态和会话数据也主要围绕本地工作区组织，难以向招聘方展示完整的 Web 前端、服务端 API、持久化、异步任务和部署能力。

本阶段将 HuiCode 扩展为一个可在浏览器中使用的 AI 编程工作台。第一期聚焦单个部署实例中的用户、工作区、项目和 Agent 会话闭环，保留现有 Agent Runtime 和安全治理能力，不追求一次完成完整的云端协作产品。

## Goals

- 让用户可以通过浏览器创建项目、发起 Agent 任务并查看实时执行过程。
- 将模型输出、工具调用、权限审批、错误、重试和完成状态统一呈现为可观察的任务时间线。
- 让会话和任务在页面刷新、网络短暂断开或服务重启后仍可恢复。
- 为不同用户和工作区提供明确的数据隔离与操作权限。
- 保留现有 CLI 使用方式，并让 Web 端复用同一套 Agent 能力和安全规则。
- 形成可本地一键启动、可测试、可部署的完整全栈作品。

## Functional Requirements

- **F1 用户与工作区**：用户可以注册、登录、退出，并查看自己所属的工作区；工作区内的数据不能被其他工作区用户越权访问。
- **F2 项目管理**：用户可以在工作区内创建、查看、重命名和归档项目；每个项目关联一个可执行的代码工作目录或项目来源。
- **F3 会话管理**：用户可以在项目内创建会话、查看会话列表、打开历史会话、重命名会话，并从已有会话继续提问。
- **F4 Agent 任务执行**：用户可以提交自然语言任务；系统需要驱动现有 Agent 能力执行模型请求、工具调用和多轮循环，并返回最终结果或明确失败原因。
- **F5 实时事件展示**：任务执行期间，用户可以实时看到文本输出、思考状态（如果提供）、工具调用开始与结束、进度、Token 使用量、错误和完成状态；事件顺序应保持一致。
- **F6 工具权限审批**：当工具调用需要用户确认时，前端应展示调用目的、目标资源和风险提示；用户可以允许、拒绝或取消，系统应将决定准确传回任务并记录结果。
- **F7 任务控制**：用户可以取消正在运行的任务；对于可恢复的失败，用户可以重新执行或继续会话，系统不得因重复请求产生重复的不可逆操作。
- **F8 会话持久化与恢复**：系统需要保存会话消息和任务事件；页面刷新、短暂断线或重新打开项目后，用户可以看到最新状态，并从中断位置继续或查看已完成结果。
- **F9 时间线与结果查看**：用户可以查看一次任务的完整时间线、工具输入输出摘要、错误信息和生成的文件变更；敏感信息不得在界面或日志中明文泄露。
- **F10 基础审计与用量**：工作区管理员可以查看成员的关键操作记录、任务状态、工具审批结果和基础用量信息（次数、耗时、Token 等）。
- **F11 CLI 兼容**：原有 CLI 启动、配置和本地交互行为不因 Web 化改造而失效；同一 Agent Runtime 的核心行为应保持一致。
- **F12 本地部署**：开发者可以按照项目文档在本机启动 Web 前端、服务端、任务执行进程和所需依赖，并完成一次从登录到任务完成的完整流程。
- **F13 任务生命周期**：每次 Agent 执行都具有明确的排队、运行、等待审批、完成、失败、取消和恢复状态；状态变化可被查询并进入任务时间线。
- **F14 任务控制与恢复**：用户可以取消任务；服务重启或执行进程异常退出后，系统能够识别失联任务，并根据任务和工具的可重试性恢复或安全标记失败。
- **F15 资源边界**：系统可以为一次任务、一次工具调用和一次 Shell 执行设置最大时长、输出大小、迭代次数和调用次数等限制；超限后任务以可解释的原因结束。
- **F16 副作用幂等**：重复提交同一个任务控制、审批或工具执行请求时，系统返回已有结果或当前状态，不重复执行已完成的不可逆操作。
- **F17 安全执行边界**：所有文件、进程、网络和外部副作用操作都经过统一的工作区路径校验、工具能力声明、权限判断和安全策略；系统提供可替换的执行后端边界。
- **F18 敏感信息保护**：敏感配置、认证信息和工具输出中的密钥在事件、日志、会话、审计和 API 响应中统一脱敏；原始敏感内容不得被普通成员读取。
- **F19 运行可观测性**：管理员和开发者可以通过任务标识关联 API 请求、Worker 执行、工具调用、错误、重试、资源消耗和最终结果；系统提供存活、就绪和基础运行指标。

## Non-Functional Requirements

- **N1 安全边界**：所有文件、Shell、MCP 和其他副作用工具继续经过现有权限、路径沙箱和危险操作拦截；Web API 不得提供绕过这些治理机制的后门。
- **N2 数据隔离**：任何项目、会话、任务、事件、文件变更和审计记录的读取与修改都必须校验用户和工作区归属。
- **N3 可恢复性**：实时连接中断后，客户端可以重新连接并补齐缺失事件；服务端不会因浏览器连接断开而默认丢弃任务。
- **N4 可观测性**：一次请求可以通过统一的任务标识关联 API 日志、Agent 事件、工具调用、错误和审计记录。
- **N5 可测试性**：核心服务、权限审批、事件流、恢复流程和关键前端交互都应有自动化测试；至少包含一个完整端到端场景。
- **N6 可维护性**：Web 接口、Agent Runtime、持久化、任务执行和前端展示之间具有清晰边界；新增前端不应要求复制一套 Agent Loop。
- **N7 部署一致性**：本地开发环境和演示环境使用同一套可复现的启动方式，配置中的密钥通过环境变量或本地未提交配置提供。
- **N8 性能基线**：在单机演示规模下，普通任务能够在合理时间内建立实时连接；事件推送不能明显阻塞其他会话，具体阈值在技术设计阶段确定并通过压测验证。
- **N9 故障可恢复**：API、Worker 或实时连接单独重启时，已持久化的任务和事件不会无提示丢失；恢复行为必须可观察、可审计。
- **N10 防御纵深**：路径沙箱、权限引擎、工具能力声明、资源限制、敏感信息脱敏和执行后端策略不能由前端参数单独绕过。
- **N11 运行一致性**：CLI 与 Web 使用相同的 Agent、工具和权限语义；生产加固不能通过复制一套仅供 Web 使用的执行逻辑实现。
- **N12 运维可操作性**：本地部署提供健康检查、日志定位、数据迁移、备份恢复和故障排查说明；关键失败应有明确错误码和处理建议。

## Out of Scope

- 跨机器分布式 Agent Team 和复杂 DAG 调度。
- 面向公众的 Skill 市场、插件市场、计费、订阅和配额售卖。
- 完整的在线 IDE 能力，包括多人同时编辑、语言服务器、编译器云端托管和任意仓库托管。
- 面向不可信代码的生产级多租户容器集群；本阶段只保留安全执行边界和可替换的执行接口。
- 完整的操作系统级隔离实现和跨机器资源调度；本阶段定义执行后端边界并提供受控的本地执行实现。
- GitHub/GitLab 的完整 OAuth、自动创建 Pull Request 和代码托管平台级功能。
- 移动端原生应用和 IDE 插件。
- 一次性完成所有历史 CLI 命令的 Web 化迁移。

## Acceptance Criteria

- **AC1**：新用户完成注册和登录后，可以进入工作区并创建项目。
- **AC2**：用户在项目中发起一个 Agent 任务，浏览器可以连续看到模型文本、工具状态和最终结果，不需要刷新页面。
- **AC3**：任务触发需要确认的工具时，浏览器出现审批界面；允许和拒绝分别导致工具继续执行或安全终止，并且历史中可见决定。
- **AC4**：用户刷新页面或主动断开网络后重新进入，会话仍显示正确的运行状态和已产生事件；正在运行的任务不会因为页面关闭而无故丢失。
- **AC5**：用户取消任务后，服务端停止后续模型和工具执行，并在时间线中显示取消结果。
- **AC6**：不同用户或工作区无法通过页面或 API 读取彼此的项目、会话、任务、文件变更和审计记录。
- **AC7**：任务完成后，用户可以查看完整时间线、工具结果摘要和文件 Diff；敏感配置值在界面和日志中被脱敏。
- **AC8**：管理员可以查看基础审计与用量信息，普通成员不能修改管理员专属数据。
- **AC9**：原有 CLI 的核心测试和交互启动仍然通过，Web 端与 CLI 使用同一套 Agent 行为和权限语义。
- **AC10**：按照部署文档启动系统后，可以使用自动化端到端测试完成“注册/登录 → 创建项目 → 发起任务 → 审批工具 → 查看结果”的完整流程。
- **AC11**：任务在运行中被取消、达到超时或超过迭代/输出预算时，最终进入对应终态，并且时间线包含原因和最后一次已知状态。
- **AC12**：Worker 在持有任务期间异常退出后，重新启动能够识别过期租约；可安全重试的任务恢复执行，不可安全重试的任务不会被静默重复执行。
- **AC13**：重复发送相同的任务控制、审批或工具执行请求不会产生重复的不可逆副作用，并返回稳定的当前状态或历史结果。
- **AC14**：使用路径穿越、符号链接、workspace 外路径、危险命令、超大输出和超时进程进行测试时，系统拒绝或终止操作，并产生可查询的审计记录。
- **AC15**：在终端、事件流、数据库记录、审计日志和 Web API 响应中输入测试密钥后，普通用户只能看到脱敏值；健康检查和运行日志能够通过 `run_id` 定位一次失败任务。
