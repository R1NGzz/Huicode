# HuiCode 面试演示准备

## 目标

用 5 分钟展示一条完整链路：模型请求工具，HuiCode 执行工具，把结果回灌给模型，再由模型决定下一步。

## 演示顺序

### 0:00 启动

```powershell
.\demo\reset-demo.ps1
.\demo\start-demo.ps1
```

介绍 HuiCode 是一个 Python 命令行 Coding Agent，当前工作区是一个可重复重置的小型项目。

### 0:30 调查项目

输入：

```text
帮我看看这个项目的代码结构
```

讲解 `Find` 的工具调用、结果摘要和下一轮模型请求。

### 1:30 读取代码

输入：

```text
读取入口文件内容
```

讲解统一 Tool 接口、工具注册中心和工具结果回灌。

### 2:30 自动修改并验证

输入：

```text
把默认问候改成中文，然后运行测试
```

讲解 Agent Loop 如何连续完成 `Read -> Edit -> Bash`，以及权限系统为什么在工具执行前介入。

### 4:00 计划模式

输入 `/plan`，再输入“规划一下如何给 greet 增加语言参数”，展示只读工具限制；输入 `/do` 返回执行模式。

### 4:40 架构收束

用下面这句话结束：

> HuiCode 的核心不是一次请求拿到答案，而是把 Provider、Agent Loop、Tool Registry、Permission Engine 和上下文历史串成一个可恢复的执行系统。

## 常见追问

| 追问 | 回答重点 |
| --- | --- |
| 为什么要抽象 Provider？ | 让 Anthropic、OpenAI 和兼容接口共享 Agent Loop，协议差异收敛在 Provider 层。 |
| 工具调用失败怎么办？ | 结构化结果回灌给模型，循环继续；达到上限或 Provider 出错才停止。 |
| 如何防止模型乱改文件？ | 黑名单、路径沙箱、规则匹配、权限模式和人在回路逐层检查。 |
| 多个 Agent 如何协作？ | 每个成员使用独立 Worktree，任务表负责事实状态，Mailbox 负责通知，最后由集成流程发布。 |
| 为什么有离线 Demo？ | 面试现场需要稳定复现核心链路，离线 Provider 只替换模型响应，工具和 Agent Loop 仍走真实实现。 |
